# План: плагин «Отметка элемента» для Navisworks

## Цель

C#-плагин для Autodesk Navisworks Manage 2021, который при наведении курсора на элемент
показывает его **отметку** (высоту) прямо в 3D-виде. Сейчас в Navisworks такой функции
нет, а при просмотре модели она постоянно требуется.

Сценарий: пользователь жмёт кнопку на ленте, курсор превращается в «отметчик»,
и при движении мыши по модели рядом с курсором появляется подпись с отметкой элемента
плюс таблица в панели над 3D-видом. `Esc` возвращает стандартный инструмент.

## Целевая платформа

| Параметр | Значение | Почему |
|---|---|---|
| ПО | Navisworks Manage **2021** | Единственная установленная версия |
| API-сборка | `Autodesk.Navisworks.Api.dll` v18.6.1399.74 | Лежит в папке установки |
| Целевой фреймворк | `net48` | Navisworks 2021 — хост на .NET Framework 4.8 |
| Разрядность | `x64` | 32-битной сборки Navisworks не существует |
| UI | WinForms-панель в 3D-виде | `Autodesk.Navisworks.Api.Controls` → `ViewControl` |
| Логика без зависимостей | `netstandard2.0` | `NavisElevation.Core` не ссылается на Navisworks |

Ссылка на API — **`<Reference>` + `HintPath`**, а не NuGet-пакет: пакета
`Navisworks.Api` не существует. Обязательно `<Private>false</Private>`: Navisworks
подгружает эти сборки сам, копия рядом с плагином ломает загрузку.

Путь к установке переопределяется при сборке:
`dotnet build -p:NavisworksInstallDir="D:\Autodesk\Navisworks Manage 2021"`

### Подтверждённые члены API

Все члены ниже проверены рефлексией по реально установленной
`Autodesk.Navisworks.Api.dll`, а не взяты из памяти.

| Задача | Член API |
|---|---|
| Элемент под курсором | `View.PickItemFromPoint(int x, int y)` → `PickItemResult` |
| Точка попадания | `PickItemResult.Point` → `Point3D` (`.Z`) — **точная** отметка под курсором |
| Границы элемента | `PickItemResult.ModelItem.BoundingBox()` → `BoundingBox3D` (`.Min.Z`, `.Max.Z`, `.Center`) |
| Отслеживание мыши | `ToolPlugin.MouseMove(View, KeyModifiers, int x, int y, double timeOffset)` |
| Включение своего курсора | `Document.Tool.SetCustomToolPlugin(ToolPlugin)` |
| Уровни и их отметки | `Document.Grids.ActiveSystem.Levels` → `GridLevel.Elevation` |
| Единицы длины | `Model.Units` → `Autodesk.Navisworks.Api.Units` |
| Кнопка в ленте | `AddInPlugin` + `PluginAttribute` + `RibbonTabAttribute` + `RibbonLayoutAttribute` |
| Панель в 3D-виде | `Autodesk.Navisworks.Api.Controls.ViewControl` |
| Имя элемента | `ModelItem.DisplayName`, `.ClassDisplayName`, `.ClassName` |

## Почему нельзя использовать базовую точку проекта

**API не отдаёт базовую точку проекта.** Прогон `Assembly.GetTypes()` по всей сборке,
включая internal-типы, не нашёл ни одного типа с `BasePoint` в имени — то есть нет
ни `BasePoint`, ни `Origin`, ни какого-либо другого доступа к нулевой точке проекта.

Поэтому «отсчитать от проектного 0» напрямую невозможно. `PickItemResult.Point.Z` —
это просто координата в собственной системе Navisworks, в единицах длины документа.
Где в этой системе ноль, зависит от того, как модель попала в Navisworks:

- **Экспорт из Revit в «Общие координаты»** → ноль Navisworks совпадает с нулём
  внутренней системы Revit, и `Z` равен внутренней отметке Revit. Но «базовая точка
  проекта» в Revit — перемещаемая точка, она **не обязана** совпадать с внутренним нулём.
- **Экспорт во «Внутренние координаты»** либо модель размещена/повёрнута в NWF
  (это `Model.Transform`) → ноль может оказаться где угодно.

### Решение: калибровка по уровням, а не по базовой точке

Navisworks **сам** хранит отметки уровней: `Document.Grids.ActiveSystem.Levels[i].Elevation`.
Это готовая встроенная проверка, базовая точка не нужна.

Калибровка на первом же реальном файле: берём элемент с заведомо известной отметкой
(балка на перекрытии, допустим `+12.000`) и смотрим, что показал плагин.

- Показало `12.000` → `Z` и есть искомая отметка, всё работает, ничего настраивать не надо.
- Показало `9.640` → разница `2.360` и есть ноль проекта.

Поэтому в отчёте всегда показываются **три величины** — отметка точки, границы
элемента и ближайший уровень с дельтой. Плюс настройка «смещение проекта» с дефолтом `0`:
если калибровка покажет ненулевое расхождение, вписываем один раз в конфиг.

### Формат отчёта

```
Элемент:    Балка / Beam 250x500
Источник:   Model-1.nwc
Отметка:    +12.000 м            ← Point.Z − смещение
Границы:    11.750 … 12.250      ← BoundingBox().Min.Z / .Max.Z
Уровень:    Уровень 3 = +12.000 (±0.000)   ← GridLevel.Elevation
```

- [x] `Reference` + `HintPath` на `Autodesk.Navisworks.Api.dll` и `Autodesk.Navisworks.Controls.dll`, `Private=false`
- [x] Солюшн, пустая сборка собирается без предупреждений

### Этап 2 — ядро логики (`NavisElevation.Core`)
- [ ] `ElevationFormatter`: значение + единицы → строка отображения
- [ ] `LevelResolver`: поиск ближайшего `GridLevel` по дельте
- [ ] `ProjectOffsetSettings`: чтение/запись смещения проекта

- [ ] `ElevationProbeTool : ToolPlugin`, перехват `MouseMove`
- [ ] `PickItemFromPoint` → `Point.Z` + `BoundingBox()`
- [ ] Троттлинг: опрос не каждый кадр, а по дельте координат и таймеру (см. риски)
- [ ] Выход по `Esc` / ПКМ с возвратом стандартного инструмента

### Этап 4 — интерфейс
- [ ] Кнопка на собственной вкладке ленты, включение режима отметки
- [ ] Подпись у курсора через `OverlayRender`
- [ ] Панель `ViewControl` с таблицей значений

### Этап 5 — поставка
- [ ] `tools/build-and-deploy.bat`: сборка и копирование в `%APPDATA%\Autodesk\Navisworks Manage 2021\Plugins\`
- [ ] Отладка: Attach to process к `Roamer.exe` (Navisworks 2021)

## Риски и что делаем, если они выстрелят

| Риск | Признак | План |
|---|---|---|
| Единицы длины | `Model.Units` отдаёт миллиметры там, где ждём метры | Сначала показываем сырой `Z` **с подписью единицы**, чтобы сверить вручную. Форматирование переключаем только после проверки |
| Тормоза на большой модели | `PickItemFromPoint` на каждом `MouseMove` (60+ Гц) роняет FPS | Опрос по дельте координат (от 3 px) и таймеру не чаще ~20 Гц |
| `ViewControl` конфликтует с нативными панелями Navisworks | Панель не вставляется или дублирует встроенную | Откат на `MessageBox` по клику — функциональность сохраняется |
| `MouseMove` не срабатывает в некоторых режимах вида | Подпись не появляется в 2D-видах | Для 2D-видов использовать `PickItemFromPoint` по событию клика |

## Контрольный список ручной проверки

Navisworks я сам запустить не могу — проверку выполняет пользователь.

- [ ] `build-and-deploy.bat` отрабатывает без ошибок, в `%APPDATA%\Autodesk\Navisworks Manage 2021\Plugins\` появился `NavisElevation.dll`
- [ ] Navisworks запускается, на ленте появилась вкладка плагина и кнопка
- [ ] По нажатию кнопки курсор превращается в отметчик, `Esc` возвращает стандартный инструмент
- [ ] При наведении на элемент появляется подпись и таблица
- [ ] **Калибровка:** навести на элемент с известной отметкой и сверить число. Расхождение — это ноль проекта, вписать в настройку смещения
- [ ] Отметка меняется при перемещении мыши по вертикали и **не** меняется вдоль одного уровня
- [ ] При наведении на пустое место подпись исчезает, а не зависает на старом значении
- [ ] Числа читаемы: видно дробную часть, ясно в каких единицах
- [ ] На модели реального размера нет заметного падения FPS
- [ ] Закрытие и повторное открытие Navisworks не приводит к ошибкам
