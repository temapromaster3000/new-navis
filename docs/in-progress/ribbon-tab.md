# План: своя вкладка на ленте

## Цель

Кнопка «Показать отметку» сейчас живёт во встроенной вкладке **Add-Ins** — это работает,
но при подключениях в проекте её приходится искать. Нужна собственная вкладка
**Navis Elevation**, чтобы кнопки плагина были видны сразу, и чтобы под новые модули
было куда добавлять панели.

Окно настроек и проверка обновлений вынесены в `settings-window.md` и `auto-update.md`.
Этап 0 дымового теста ленты и окна уже выполнен.

## Что уже известно

| Вопрос | Ответ |
|---|---|
| Нужен ли XAML | **Да, обязательно.** Без `[RibbonLayout]` вкладка не появляется и никакой ошибки не выдаёт |
| Базовый класс | **`CommandHandlerPlugin`**, а не `AddInPlugin`. Только он несёт `[RibbonLayout]` и `[RibbonTab]` |
| Где брать образец | Вкладка **BIM 360 Glue** из самой поставки Navisworks: `ru-RU\GlueRibbon.xaml`. Все имена пространств имён и набор атрибутов взяты оттуда |
| Пространства имён | `AdWindows` = `Autodesk.Windows` (типы `RibbonControl`, `RibbonTab`, `RibbonPanel`, `RibbonPanelSource`), `local:` = `Autodesk.Navisworks.Gui.Roamer.AIRLook` из `navisworks.gui.roamer.dll` (тип `NWRibbonButton`) |
| Где ищется файл разметки | **Файлом в языковой подпапке рядом с плагином**: `ru-RU` для русского интерфейса, `en-US` как запасной. Рядом лежит файл локализации `*.name`, на который указывает `[Strings]`. Так описано в блоге Autodesk: «the xaml and name file must reside in the sub-folder of the plug-in dll. The sub-folder name needs to be a Language Code». Встроенные плагины Navisworks устроены так же: `ru-RU\RenderTab.xaml`, `ru-RU\GlueRibbon.xaml` |
| Почему не ресурс в сборке | Navisworks разметку в сборке не ищет. Проверено: и обычный `EmbeddedResource` с XAML, и контейнер `<сборка>.Resources.resources` со строковым ресурсом — вкладка не появляется, в логе пусто |
| Что за файл `.name` | Обычный текст UTF-8 с локализованными названиями: `<идентификатор>.DisplayName=` и текст на следующей строке. Приоритет: сначала строки из XAML, потом из `.name`, потом из атрибутов класса. Нужен, чтобы вкладка выглядела одинаково у коллеги с английским Navisworks |
| Нужен ли `navisworks.gui.roamer` в ссылках | **Да.** По форуму Autodesk: пока эта сборка не подключена, в папке плагина не появляются языковые подпапки, и разметка не находится |
| Как выглядит в коде | У класса `ElevationRibbon` атрибуты `[RibbonLayout("RibbonDefinition.xaml")]`, `[Strings("NavisElevation.name")]`, `[RibbonTab(PluginIds.TabId)]` |
| Иконки | Их удобнее задать атрибутом `[Command(Icon = "...16.png", LargeIcon = "...32.png")]`: путь считается от папки с DLL. Если прописать `Image` в разметке, оно перекроет атрибут |
| Размеры иконок | `Image` — 16×16, `LargeImage` — 32×32, для крупной кнопки `Size="Large"` |

Образец класса из репозитория сэмплов Autodesk:

```csharp
[Plugin("CASERibbon", "CASE", DisplayName = "CASE Ribbon")]
[RibbonLayout("CustomRibbon.xaml")]
[RibbonTab("ID_CustomTab_1", DisplayName = "CASE")]
[Command("ID_Navis2BCF", DisplayName = "BCF Exporter",
         Icon = "navis2bcf16x16.ico", LargeIcon = "navis2bcf32x32.ico")]
class CASERibbon : CommandHandlerPlugin
```

## Почему кнопок нет во встроенной вкладке Add-Ins

`AddInPlugin` и `CommandHandlerPlugin` — разные базовые классы, а наследование в C#
одинарное. Совместить их в одном классе нельзя, а вывод команды во встроенную вкладку
даёт именно атрибут `[AddInPlugin(AddInLocation.AddIn)]`.

Решено так: **плагин живёт только на своей вкладке.** Класс `ElevationRibbon` несёт
`[RibbonLayout]`, `[RibbonTab]` и обе `[Command]`, а класса-наследника `AddInPlugin`
в проекте нет вообще. Общая логика включения режима вынесена в `ProbeToggle`, чтобы
она не дублировалась.

| Класс | Роль |
|---|---|
| `ElevationRibbon : CommandHandlerPlugin` | собственная вкладка, обе кнопки |
| `ElevationProbeTool : ToolPlugin` | инструмент, следящий за курсором |
| `ProbeToggle` | общая логика включения режима, зовут её обе кнопки |

Плата за решение: если Navisworks перестанет читать файл разметки, кнопок не будет
нигде, и лога тоже не будет — сборка просто не загрузится. Раньше кнопка в Add-Ins
оставалась бы доступной. Подробности — в рисках ниже.

## Риски

| Риск | Признак | Что делать |
|---|---|---|
| Вкладка не появилась | Нет ни вкладки, ни ошибки | Проверять по порядку: лежат ли `RibbonDefinition.xaml` и `NavisElevation.name` в `Contents\2021\ru-RU`, совпадает ли `Id` вкладки в разметке с `[RibbonTab]`, перезапущен ли Navisworks после выкладки. Если Navisworks поменяет правила поиска — положить эти файлы в корень бандла |
| Нигде нет кнопок и нет лога | Плагин не загрузился | Это и есть признак сломанной выкладки: лог создаётся при загрузке сборки. Разбираться с `PackageContents.xml` |
| Кнопка в панели, но не нажимается | Нажатие без эффекта | `Id` в `NWRibbonButton` обязан совпадать с id в `[Command]`, а `[Command]` обязан быть на классе, который несёт `[RibbonLayout]` |
| Иконки не видны | Пустой квадрат | Проверить размеры 16 и 32 и что PNG действительно вшиты в сборку |
| Лента ломает всё остальное | Кнопок нет нигде | Откат на версию без `[RibbonLayout]`: класс `ElevationRibbon` можно убрать из сборки — но тогда кнопок не будет вообще, так что откат полезен только как разовая проверка |
