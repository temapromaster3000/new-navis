# План: окно настроек

## Цель

Окно с версией плагина, калибровкой отметки и проверкой обновлений — вместо того, чтобы
калибровку задавать ручной правкой файла `settings.txt`.

Сейчас плагин открывает только подпись у курсора. Окно нужно, чтобы пользователь мог
посмотреть версию и понять, откуда она взялась, и задать калибровочное смещение, не
залезая в файлы.

## Что уже известно

| Вопрос | Ответ |
|---|---|
| Открывается ли WPF-окно поверх Navisworks | **Ещё не проверено.** Дымовой тест собран (этап 0), ждёт запуска пользователя. WPF в процессе Navisworks должен работать: GUI самой программы (`navisworks.gui.roamer.dll`) ссылается на PresentationFramework, PresentationCore и WindowsBase, то есть интерфейс Navisworks сам на WPF. Если окно не откроется — откат на WinForms, и больше ничего в плане менять не придётся |
| Что показать сверху окна | `navisworks.gui.roamer.dll` лежит рядом с `Autodesk.Windows.dll`, **не рядом с нами**. Значит `<Reference Include="Autodesk.Windows" />` без `HintPath` разрешится в сборку Navisworks, а не в нашу, и это ломает компиляцию |
| Как задать родительское окно | У WPF `Window.Owner` принимает объект `Window`, а не `HWND`. Родителя задаём через `WindowInteropHelper` — единственный способ привязать окно к нативному родителю |
| Нужны ли права администратора | Нет, окно живёт в процессе Navisworks, на диск ничего не пишет |
| Куда писать калибровку | В `%APPDATA%\NavisElevation\settings.txt`. Метод `ProjectSettings.Save()` был удалён как мёртвый код и должен вернуться — с правильным текстом: смещение в метрах, прибавляется после перевода |

## Интерфейс собирается в коде, а не в XAML

Компилятор разметки WPF в проектах под .NET Framework недоступен — проверено сборкой,
`InitializeComponent` не генерировался, пока `<Page>` не был убран. Поэтому окно
собирается из `TextBlock`, `Button` и `Border` прямо в C#. Для окна с десятком элементов
это проще, чем заводить файл разметки, который пришлось бы собирать обходными путями.

**Разметка XAML при этом нужна ленте** — она встраивается как `EmbeddedResource`, и
Navisworks читает её как текст.

## Риски

| Риск | Признак | Что делать |
|---|---|---|
| Окно открывается сзади Navisworks | Видно окно, но не поверх | Не сработал `WindowInteropHelper` — проверить запись в логе о привязке родителя |
| Окно не открывается вообще | Ничего не произошло | Запись «Окно настроек открыто и загружено» в логе есть или нет |
| Ошибка компиляции на `Autodesk.Windows` | Не найдено пространство имён | Ссылка без `HintPath` уехала в Navisworks — задавать путь явно |
| Смещение записалось не туда | Значение не применилось | Проверить формат `ProjectOffset=2.36` и что файл читается из `%APPDATA%` |
| Смещение применяется сразу, но не сохраняется | После перезапуска слетело | Файл не создан — у пользователя может не быть прав на запись в `%APPDATA%` |

## Контрольный список ручной проверки

Navisworks агент запустить не может — проверка за пользователем.

- [ ] Окно открывается поверх Navisworks и поверх всех окон модели
- [ ] Версия в окне совпадает с `Version.txt`
- [ ] Введённое смещение применяется к отметке сразу после нажатия «Применить»
- [ ] Смещение переживает перезапуск Navisworks
- [ ] Кнопка сброса возвращает нулевое смещение
- [ ] Закрытие окна кнопкой и крестиком работает одинаково
- [ ] Окно не перекрывает кнопки ленты и не уезжает за край экрана
