# План: проверка и установка обновлений

## Цель

Кнопка в окне настроек: посмотреть, вышла ли новая версия на GitHub, скачать её и
поставить. Версию плагина вручную не отслеживать — сейчас пользователь обновляется,
запуская `build-and-deploy.bat` вручную.

Образец для переноса — обновлялка в собственном плагине для Revit,
`src/AssemblingManager.Revit/Updates/UpdateService.cs` и `src/AssemblingManager.Updater/`.
Схема рабочая и уже обкатана, переносится почти целиком.

## Что уже известно

| Вопрос | Ответ |
|---|---|
| Откуда брать список релизов | `https://api.github.com/repos/temapromaster3000/new-navis/releases?per_page=20`. Фильтровать `draft` и `prerelease` |
| Как сравнивать версии | Отдельный класс `PluginVersion` в `NavisElevation.Core` с разбором `major.minor.patch` — копия из Revit-плагина. Ядро не зависит от Navisworks, класс туда и ложится |
| Откуда брать версию своей | `Version.txt` через метаданные сборки. Он уже единственный источник версии в проекте |
| Главная сложность | DLL в бандле **заблокирована**, пока Navisworks запущен. Перезаписать её изнутри процесса нельзя |
| Как это решено в Revit-плагине | Скачанное раскладывается в staging, пишется маркер `update-pending.txt`, запускается отдельный `Updater.exe`, который **ждёт закрытия хоста** и только потом подменяет DLL |
| Что ждать вместо Revit | Процесс `Roamer.exe` вместо `Revit.exe` |
| Нужен ли установщик | **Нет.** У Revit-плагина стоит Inno Setup, но обновление всё равно только подменяет DLL. У нас выкладка идёт бат-файлом в бандл — значит и обновление подменяет DLL в бандле |
| Инструменты на машине | `gh` 2.99.0 установлен, нужен `gh auth login`. Inno Setup не установлен и не требуется |

## Состояние на сейчас

В репозитории `new-navis` **ноль релизов и ноль тегов**. До первой публикации кнопка
обновления будет честно отвечать «у вас последняя версия» — это правильное поведение, но
проверить механизм на живом релизе можно будет только после выхода версии. Релиз
публикуется в самом конце, по команде пользователя.

## Этапы

- [ ] `PluginVersion` в `NavisElevation.Core` — разбор и сравнение версий
- [ ] `UpdateService`: запрос GitHub Releases API, фильтр черновиков и превью, поиск
      новой версии, выбор файла под Navisworks 2021
- [ ] Скачивание в `%APPDATA%\NavisElevation\staging` с прогрессом
- [ ] Маркер `update-pending.txt` со списком файлов на замену
- [ ] Проект `NavisElevation.Updater` (net48, консоль, без зависимостей): ждёт закрытия
      `Roamer.exe`, подменяет DLL в бандле, чистит staging и маркер
- [ ] Запуск апдейтера из окна настроек
- [ ] `tools/release.ps1` и `tools/release.bat` — публикация релиза через `gh`
- [ ] Первый релиз — по команде пользователя

## Куда класть апдейтер

Рядом с плагином, в папке бандла `Contents\2021\`. Navisworks грузит только DLL из
`ModuleName`, лишний `.exe` в этой папке помешать не должен — **это нужно проверить на
практике**. Если помешает, альтернатива: `%APPDATA%\NavisElevation\`, туда же, где лог
и настройки, а `build-and-deploy.bat` будет копировать туда апдейтер.

## Риски

| Риск | Признак | Что делать |
|---|---|---|
| Нет сети или GitHub недоступен | Ошибка в окне | Показывать понятный текст, а не исключение. Обновление — необязательная функция, плагин должен работать без него |
| Нет прав на запись в бандл | Ошибка при подмене | Писать причину в лог апдейтера, не молчать |
| Апдейтер не дождался закрытия Navisworks | Файл не подменён | У апдейтера свой лог и таймаут ожидания, как в Revit-плагине |
| Пользователь не доверяет автозамене | — | Спросить перед запуском апдейтера, а не молча запускать |
| ZIP релиза не найден под 2021 | Ошибка поиска файла | Жёстко требовать наличие нужного ассета в релизе, иначе сообщение прямо об этом |

## Контрольный список ручной проверки

Navisworks агент запустить не может — проверка за пользователем.

- [ ] При отсутствии новых версий окно пишет «у вас последняя версия»
- [ ] После публикации тестового релиза обновление находится
- [ ] Показывается список изменений из релиза
- [ ] Скачивание идёт с прогрессом и не блокирует Navisworks
- [ ] После закрытия Navisworks DLL подменяется, при следующем запуске в окне новая версия
- [ ] При отсутствии сети показывается понятное сообщение, плагин продолжает работать
- [ ] Лог апдейтера создан в `%APPDATA%\NavisElevation\`
