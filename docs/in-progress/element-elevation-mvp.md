# План: плагин «Отметка элемента» для Navisworks

## Цель

C#-плагин для Autodesk Navisworks Manage 2021, который при наведении курсора на элемент
показывает его **отметку** (высоту) прямо в 3D-виде. Сейчас в Navisworks такой функции
нет, а при просмотре модели она постоянно требуется.

Сценарий: пользователь жмёт кнопку на ленте, и при движении мыши по модели рядом с
курсором появляется подпись с отметкой элемента. `Esc`, правая кнопка мыши или повторное
нажатие кнопки возвращают стандартный инструмент.

---

## Целевая платформа

| Параметр | Значение | Почему |
|---|---|---|
| ПО | Navisworks Manage **2021** | Единственная установленная версия |
| API-сборка | `Autodesk.Navisworks.Api.dll` v18.6.1399.74 | Лежит в папке установки |
| Целевой фреймворк | `net48` | Navisworks 2021 — хост на .NET Framework 4.8 |
| Разрядность | `x64` | 32-битной сборки Navisworks не существует |
| UI | Подпись в оверлее 3D-вида | `ToolPlugin.OverlayRender` → `Graphics.Text2D` |
| Логика без зависимостей | `netstandard2.0` | `NavisElevation.Core` не ссылается на Navisworks |

Ссылка на API — **`<Reference>` + `HintPath`**, а не NuGet-пакет: пакета
`Navisworks.Api` не существует. Обязательно `<Private>false</Private>`: Navisworks
подгружает эти сборки сам, копия рядом с плагином ломает загрузку.

Путь к установке переопределяется при сборке:
`dotnet build -p:NavisworksInstallDir="D:\Autodesk\Navisworks Manage 2021"`

## Архитектура

| Слой | Проект | TFM | Ответственность |
|---|---|---|---|
| Core | `NavisElevation.Core` | `netstandard2.0` | Форматирование отметки, поиск ближайшего уровня, настройка смещения, диагностический лог. **Без ссылок на Navisworks** |
| Navis | `NavisElevation.Navis` | `net48` | `ToolPlugin` с перехватом мыши, кнопка, подпись в оверлее, чтение данных из документа |

Исходники `Core` **компилируются прямо в сборку плагина** через `<Compile Include>`, а не
подключаются как `ProjectReference`. Причина практическая: Navisworks загружает сборку
плагина сам и не гарантирует разрешение второй сборки рядом с ней, а такая ошибка молча
нигде не сообщается. В папку плагина кладётся одна DLL.

### Куда и как ставится плагин

```
%APPDATA%\Autodesk\ApplicationPlugins\NavisElevation.bundle\
├── PackageContents.xml
└── Contents\2021\
    └── NavisElevation.dll
```

Это **AppBundle** — документированный Autodesk способ установки плагина Navisworks
без прав администратора. Описание бандла лежит в репозитории: `deploy\PackageContents.xml`.

Три требования, каждое из которых нарушается молча, без единой ошибки:

| Требование | Что будет, если не так |
|---|---|
| `PackageContents.xml` в корне бандла | Бандл не подхватывается вообще |
| `AppType="ManagedPlugin"` в `ComponentEntry` | Бандл не считается управляемым .NET-плагином |
| `SeriesMin`/`SeriesMax` = `Nw18` | Компонент не применяется. Серии: Nw17=2020, **Nw18=2021**, Nw19=2022 |

`ModuleName` задаёт точный относительный путь к сборке, поэтому имя папки внутри
`Contents` может быть любым. Папка `en-US` не нужна: она требуется только плагинам с
собственным XAML файлом ленты.

### Почему не папка Plugins и не просто DLL

Navisworks 2021 автозагружает плагины **только** из папки `Plugins` внутри папки
установки — `C:\Program Files\Autodesk\Navisworks Manage 2021\Plugins`. Запись туда
требует прав администратора, а у пользователя их нет.

Папка `%APPDATA%\Autodesk\Navisworks Manage 2021\Plugins` была первоначальной версией
этого плана и **не работает**. Проверено опытом, а не предположением: плагин был
разложен туда, Navisworks запущен позже — и `%LOCALAPPDATA%\NavisElevation\plugin.log`
не появился, то есть сборка не была загружена вообще. Строка с путём
`Autodesk\ApplicationPlugins` найдена в `Roamer.exe` установленной сборки, а строки с
пользовательской папкой `Navisworks Manage 2021\Plugins` в бинарниках нет.

**Урок, который стоит помнить:** существование папки с правильной DLL ничего не
значит. Проверять надо не папку, а лог плагина.

Все члены ниже проверены рефлексией по реально установленной

| Задача | Член API |
|---|---|

| Включение своего курсора | `Document.Tool.SetCustomToolPlugin(ToolPlugin)` |
| Уровни и их отметки | `Document.Grids.ActiveSystem.Levels` → `GridLevel.Elevation` |
| Единицы длины | `Model.Units` → `Autodesk.Navisworks.Api.Units` |
| Кнопка в ленте | `AddInPlugin` + `PluginAttribute` + `RibbonTabAttribute` + `RibbonLayoutAttribute` + `CommandAttribute` |
| Подпись у курсора | `ToolPlugin.OverlayRender(View, Graphics)` → `Graphics.Text2D(TextFontInfo, string, Point2D.Origin, int x, int y)` между `BeginWindowContext()` / `EndWindowContext()` |
| Перерисовка оверлея | `View.RequestDelayedRedraw(ViewRedrawRequests.OverlayRender)` |
| Подсветка элемента | `DocumentModels.OverrideTemporaryColor(IEnumerable<ModelItem>, Color)` и `ResetTemporaryMaterials(IEnumerable<ModelItem>)` — сброс **по списку**, побочных эффектов на другие плагины нет |
| Возврат стандартного инструмента | `Document.Tool.Set(Tool)`; значение `Tool.CustomToolPlugin` означает, что активен наш инструмент |
| Имя элемента | `ModelItem.DisplayName`, `.ClassDisplayName`, `.ClassName` |
| Модель-владелец элемента | подъём по `ModelItem.Parent` до корня и сверка с `Model.RootItem` у каждой `Document.Models` |
| Имя файла модели | `Model.FileName`, `Model.SourceFileName` |

### Чего в API нет (проверено, чтобы не искать снова)

| Чего ожидали | Что на самом деле |
|---|---|
| `ViewControl` внутри 3D-вида | **Невозможно.** У `View` нет ни одного метора для показа панели — поиск по слову `ViewControl` по всей сборке даёт ноль совпадений. Сам `ViewControl` — обычный `System.Windows.Forms.Control`, но подвесить его нечем. Свою панель можно сделать только как `DockPanePlugin` (док-панель сбоку) |
| Базовая точка проекта | Отсутствует полностью, см. следующий раздел |
| `Autodesk.Navisworks.Api.MessageBox` | Не существует. Сообщить пользователю о невозможности действия можно только через `CommandState.IsEnabled` — кнопка просто гаснет |
| `DocumentModels.ResetTemporaryMaterials()` без аргументов | Метод требует `IEnumerable<ModelItem>`. Это лучше, чем ожидалось: сбрасывается только наш элемент |

## Почему нельзя использовать базовую точку проекта

**API не отдаёт базовую точку проекта.** Прогон `Assembly.GetTypes()` по всей сборке,
включая internal-типы, не нашёл ни одного типа с `BasePoint` в имени — то есть нет
ни `BasePoint`, ни `Origin`, ни какого-либо другого доступа к нулевой точке проекта.

Поэтому «отсчитать от проектного 0» напрямую невозможно. `PickItemResult.Point.Z` —
это просто координата в собственной системе Navisworks, в единицах длины документа.
Где в этой системе ноль, зависит от того, как модель попала в Navisworks:

- **Экспорт из Revit в «Общие координаты»** → ноль Navisworks совпадает с нулём
  внутренней системы Revit, и `Z` равен внутренней отметке Revit. Но «базовая точка
  проекта» в Revit — перемещаемая точка, она **не обязана** совпадать с внутренним нулём.
- **Экспорт во «Внутренние координаты»** либо модель размещена/повёрнута в NWF
  (это `Model.Transform`) → ноль может оказаться где угодно.

### Решение: калибровка по уровням, а не по базовой точке

Navisworks **сам** хранит отметки уровней: `Document.Grids.ActiveSystem.Levels[i].Elevation`.
Это готовая встроенная проверка, базовая точка не нужна.

Калибровка на первом же реальном файле: берём элемент с заведомо известной отметкой
(балка на перекрытии, допустим `+12.000`) и смотрим, что показал плагин.

- Показало `12.000` → `Z` и есть искомая отметка, всё работает, ничего настраивать не надо.
- Показало `9.640` → разница `2.360` и есть ноль проекта.

Поэтому в подписи всегда показываются **несколько величин** сразу: отметка точки, её
сырое значение в единицах модели, границы элемента и ближайший уровень с дельтой.
Плюс настройка «смещение проекта» с дефолтом `0`: если калибровка покажет ненулевое
расхождение, вписываем один раз в конфиг.

### Формат подписи

Отметка всегда показывается **в метрах**, независимо от единиц модели: модель может
прийти в футах или дюймах, но отметки в чертежах пишут в метрах. Исходное число в
единицах модели стоит рядом в скобках — по нему видно, в каких единицах модель, и по
нему же проверяется калибровка.

```
Балка / Beam 250x500
Отметка: +3.000 м (9.843 фт)
Границы: +2.700 м … +3.000 м
Уровень Уровень 3: +12.000 м (на уровне)
Модель: Model-1.nwc
```

Строка «Уровень» появляется, только если в модели есть уровни, строка «Модель» — если
у элемента нашлась модель-владелец.

**Калибровочное смещение задаётся в метрах и прибавляется после перевода в метры.**
Порядок важен: вычитать метры из футов бессмысленно. Первая версия форматтера именно
так и делала — печатала сырое число и подписывала его единицами модели, из-за чего
модель в футах показывала `9.843 фт` вместо `3.000 м`.

Смещение задаётся файлом `%APPDATA%\NavisElevation\settings.txt`:

```
ProjectOffset=2.36
```

### Чего пока нет

- Док-панели с таблицей — вместо неё подпись у курсора. Панель потребовала бы
  `DockPanePlugin` и заметно больше кода, а MVP проверяется быстрее.
- Иконки кнопки.

## Риски и что делаем, если они выстрелят

| Риск | Признак | План |
|---|---|---|
| Единицы длины | `Model.Units` отдаёт миллиметры там, где ждём метры | В подписи показываем **обе** величины: «+12.345 м (12345,678 мм)». Сверить можно вручную, ничего не перенастраивая |
| Тормоза на большой модели | `PickItemFromPoint` на каждом `MouseMove` (60+ Гц) роняет FPS | Уже стоит троттлинг: 3 px и 40 мс. Если мало — поднять до 60 мс |
| `Text2D` не рисует текст | Подпись не появляется, а элемент подсвечивается | Проверить `CanRenderText2D`; если недоступен в текущем контексте — перейти на `DockPanePlugin` |
| Исключение при отрисовке | В логе Navisworks ошибка на каждом кадре | `OverlayRender` обёрнут в try/catch и молча пропускает кадр: просмотр не должен падать из-за подписи |
| `MouseMove` не срабатывает в 2D-видах | Подпись не появляется в планах и разрезах | Для 2D-видов использовать `PickItemFromPoint` по событию клика |
| Кнопка без иконки выглядит пустой | В ленте пустой квадрат | Добавить PNG как ресурс и указать `CommandAttribute.Icon` |
| Бандл не подхватывается | Нет лога и нет вкладки Add-Ins | Проверить `PackageContents.xml`: `AppType="ManagedPlugin"`, `SeriesMin`/`SeriesMax` = `Nw18`, совпадение `ModuleName` с фактическим путём DLL. Всё это проверяется только логом: ошибок Navisworks не выдаёт |
| Режим не включается, `NullReferenceException` | В логе «Не удалось включить режим отметки» и стек | `SetCustomToolPlugin` требует экземпляр из `PluginRecord.LoadPlugin()`, а не созданный через `new`: у экземпляра вручную поле `PluginRecord` равно `null`, и Navisworks падает внутри себя. Плюс у инструмента должен быть конструктор без параметров |
| Отметка не появляется | В логе нет строки «Элемент под курсором» после наведения | `PickItemFromPoint` ничего не нашёл: элемент не под курсором или не виден в текущем виде |

### Диагностический лог

Плагин пишет `%LOCALAPPDATA%\NavisElevation\plugin.log`. Файл создаётся **в момент загрузки
сборки** — из статического конструктора класса плагина, а не по нажатию кнопки. Это и было
причиной первой пустой проверки: лог начинался только в `Execute`, а кнопку нажать нельзя,
так что по отсутствию файла нельзя было сказать ничего.

Присылай содержимое файла — по нему видно, до какого места дошло выполнение.

| Что в логе | О чём говорит |
|---|---|
| Файла нет | Navisworks не коснулся сборки вообще. Проверь структуру бандла (см. ниже) и что Navisworks перезапущен после выкладки |
| Есть «Сборка плагина загружена» | Сборка загружена — вкладка Add-Ins обязана появиться. Дальше смотри следующую строку |
| Есть «Плагин команды загружен, OnLoaded» | Плагин полностью инициализирован Navisworks |
| Есть «Кнопка нажата» | Кнопка работает, режим включается |
| «Кнопка нажата», но нет «Элемент под курсором» | `PickItemFromPoint` ничего не находит — проверяем модель и видимость |
| «Элемент под курсором» со строкой `Z=…` | Захват работает. Смотри `Z` и ищи расхождение с ожидаемой отметкой |
| «уровней в модели: 0» | В модели нет уровней, строка «Уровень» не появится — это нормально |
| Строка `[ERROR]` | Причина исключения записана рядом |

### Что проверить, если кнопка не появилась

Проверять в первую очередь **лог**, а не глазами искать вкладку: он сразу говорит, грузилась
ли сборка. Если лог пуст, порядок такой:

1. Структура бандла совпадает с показанной выше, а `ModuleName` в `PackageContents.xml`
   указывает на DLL, которая реально лежит по этому пути. Опечатка в пути внутри XML
   означает молчаливое игнорирование.
2. В `PackageContents.xml` стоит `AppType="ManagedPlugin"` и `SeriesMin`/`SeriesMax` = `Nw18`.
3. В папке плагина **одна** DLL `NavisElevation.dll` — никаких `.Core.dll` рядом.
4. Navisworks был перезапущен **после** выкладки. Бандлы читаются только при старте,
   и выкладка в уже открытый Navisworks не подхватывается никогда.
5. Лента не свёрнута. В Navisworks ленту можно скрыть — тогда вкладок не видно, но они есть.
6. Если лог всё ещё пуст, отдели «плохой XML» от «плохого кода», запустив Navisworks
   напрямую с указанием сборки:
   `Roamer.exe -AddPluginAssembly "<путь>\Contents\2021\NavisElevation.dll"`.
   Ключ поддерживается этой версией — строка `AddPluginAssembly` есть в
   `navisworks.gui.roamer.dll`. Лог Navisworks пишется ключом `-log "<путь>\файл.txt"`.
7. Visual Studio: Debug → Attach to Process → `Roamer.exe`, поставить точку останова в
   `ElevationProbeTool` и посмотреть, грузится ли сборка.
