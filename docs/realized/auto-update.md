# План: проверка и установка обновлений

> **Статус: реализовано.** Кнопка «Проверить обновления» в окне настроек, скачивание
> релиза с GitHub и подмена файлов плагина отдельной программой после закрытия
> Navisworks. Вместе с этим — установщик `setup.exe` и релиз 1.0.0, опубликованный
> на GitHub: <https://github.com/temapromaster3000/new-navis/releases/tag/v1.0.0>.
>
> Проверено в Navisworks Manage 2021: кнопка отвечает «у вас последняя версия», лог
> пишет ход проверки. Сам цикл обновления (скачать → подменить → перезапустить)
> проверен автоматической проверкой на поддельном GitHub, а не на живом релизе:
> новее 1.0.0 на тот момент ничего не было.

## Цель

Кнопка в окне настроек: посмотреть, вышла ли новая версия на GitHub, скачать её и
поставить. Версию плагина вручную не отслеживать — сейчас пользователь обновляется,
запуская `build-and-deploy.bat` вручную.

Образец для переноса — обновлялка в собственном плагине для Revit,
`src/AssemblingManager.Revit/Updates/UpdateService.cs` и `src/AssemblingManager.Updater/`.
Схема рабочая и уже обкатана, переносится почти целиком.

## Решения, принятые при реализации

| Вопрос | Решение | Почему |
|---|---|---|
| Нужны ли новые NuGet-пакеты | **Нет** | `HttpClient`, `ZipFile` и разбор JSON берём из самого .NET Framework 4.8: `System.Net.Http`, `System.IO.Compression.FileSystem` и `System.Web.Extensions` (`JavaScriptSerializer`). Наивный `System.Text.Json` тянул бы 7 лишних DLL рядом с плагином, а Navisworks может их не подхватить — и всё упадёт молча |
| Где живёт обновлятель | `%APPDATA%\NavisElevation\NavisElevation.Updater.exe`, **вне бандла** | DLL плагина в бандле заблокирована, пока открыт Navisworks, поэтому подменять её может только отдельный процесс. В бандл обновлятель не кладём, чтобы не мешать загрузчику плагинов Navisworks |
| Когда проверяется релиз | **Только по кнопке** в окне настроек | Плагин не ходит в сеть сам: никаких лишних запросов и никаких вопросов «почему он что-то скачивает» |
| Спрашивать ли перед подменой | **Да** | Обновление меняет файлы плагина. Молча такое делать нельзя |
| Какой релиз публикуем | **1.0.0**, тег `v1.0.0` | Первая публичная версия плагина, с установщиком |
| Состав релиза | `NavisElevation-1.0.0-setup.exe` (Inno Setup) + `NavisElevation-2021.zip` (файл автообновления) | Как в Assembling Manager: установщик для человека и ZIP для плагина |
| Где взять Inno Setup | `D:\Soft\Inno Setup 6\ISCC.exe` | На этой машине установлен, `Russian.isl` тоже на месте |

## Состояние на сейчас

В репозитории `new-navis` **ноль релизов и ноль тегов**. До первой публикации кнопка
обновления будет честно отвечать «у вас последняя версия» — это правильное поведение, но
проверить механизм на живом релизе можно будет только после выхода версии. Релиз
публикуется в самом конце, по команде пользователя.

### Находки, которые стоит помнить

- **`Compress-Archive` и `ZipFile.CreateFromDirectory` в .NET Framework пишут в записи
  архива обратные слэши**, а это не по правилам формата ZIP. Наша распаковка такой
  архив читает, но архив собирается вручную, с прямыми слэшами.
- **`git describe --tags` падает, когда тегов нет**, а с `$ErrorActionPreference =
  "Stop"` это обрывает скрипт релиза. Теги берутся через `cmd /c`, где ошибка git не
  становится исключением PowerShell.
- **Лог обновлятеля пишется рядом с маркером**, а не в фиксированную папку: иначе
  проверка обновлятеля писала бы в настоящий журнал пользователя.
- **Обновлятель удаляет только те папки, что перечислены в маркере.** Удаление папки
  «staging» по умолчанию могло бы снести не то место.

## Куда класть апдейтер

**В `%APPDATA%\NavisElevation\NavisElevation.Updater.exe` — вне бандла.** Первоначально
планировалось положить его рядом с плагином, в `Contents\2021\`, но это лишний риск:
Navisworks читает бандл своим загрузчиком, и лишний файл в папке с DLL может помешать.
Отдельная папка рядом с логом и настройками безопаснее, а `build-and-deploy.bat` и
установщик `setup.exe` раскладывают обновлятель именно туда.

Сам обновлятель себя не обновляет: работающую программу нельзя перезаписать. Обновление
обновлятеля — только через полную переустановку. Это же ограничение зафиксировано в
Revit-плагине.

## Риски

| Риск | Признак | Что делать |
|---|---|---|
| Нет сети или GitHub недоступен | Ошибка в окне | Показывать понятный текст, а не исключение. Обновление — необязательная функция, плагин должен работать без него |
| Нет прав на запись в бандл | Ошибка при подмене | Писать причину в лог апдейтера, не молчать |
| Апдейтер не дождался закрытия Navisworks | Файл не подменён | У апдейтера свой лог и таймаут ожидания, как в Revit-плагине |
| Пользователь не доверяет автозамене | — | Спросить перед запуском апдейтера, а не молча запускать |
| ZIP релиза не найден под 2021 | Ошибка поиска файла | Жёстко требовать наличие нужного ассета в релизе, иначе сообщение прямо об этом |
| GitHub вернул 403 (лимит запросов) | Ошибка в окне | Показывать, когда лимит сбросится, а не сырое исключение |
| JSON не разобрался | Ошибка в окне | `JavaScriptSerializer` из `System.Web.Extensions` разбирает ответ GitHub без внешних пакетов. Проверяется на живом ответе до публикации релиза |
| Обновлятель не успел заменить файлы | Файлы старые | У обновлятеля свой лог и таймаут ожидания, а копирование повторяется при занятом файле |
| Установщик требует прав администратора | Ошибка установки | `PrivilegesRequired=lowest`, бандл ставится в `%APPDATA%` — права администратора не нужны |

## Что лежит в файле обновления

Релиз на GitHub содержит два файла:

| Файл | Для кого |
|---|---|
| `NavisElevation-2021.zip` | Для плагина: его скачивает кнопка «Проверить обновления» |
| `NavisElevation-1.0.0-setup.exe` | Для человека: установщик для коллеги, ставит всё с нуля |

Внутри `NavisElevation-2021.zip` — ровно то, что лежит в `Contents\2021` бандла:
сборка плагина, иконки кнопок и папки `ru-RU` и `en-US` с разметкой ленты и файлом
локализации. Обновлятель копирует дерево как есть, поэтому структура папок сохраняется.

## Контрольный список ручной проверки

Navisworks агент запустить не может — проверка за пользователем.

- [x] При отсутствии новых версий окно пишет «у вас последняя версия»
- [ ] После публикации тестового релиза обновление находится
- [ ] Показывается список изменений из релиза
- [ ] Перед подменой файлов спрашивается подтверждение
- [ ] Скачивание идёт с прогрессом и не блокирует Navisworks
- [ ] После закрытия Navisworks DLL подменяется, при следующем запуске в окне новая версия
- [ ] При отсутствии сети показывается понятное сообщение, плагин продолжает работать
- [ ] Лог апдейтера создан в `%APPDATA%\NavisElevation\`
- [ ] `setup.exe` ставит плагин без прав администратора, вкладка появляется
- [ ] После установки `setup.exe` в `%APPDATA%\NavisElevation\` лежит обновлятель

Первый пункт проверен: в логе от 2026-10-20 видно шесть проверок, все шесть
ответили «новых версий нет» — так и должно быть, пока на GitHub нет релиза
новее установленной версии.

Остальные пункты требуют релиза новее 1.0.0: на момент публикации обновляться
было нечему, и путь «скачать → подменить → перезапустить» проверен автоматической
проверкой на поддельном GitHub, а не на живом обновлении. Чтобы увидеть весь цикл
вживую, нужен следующий релиз — например 1.0.1.
