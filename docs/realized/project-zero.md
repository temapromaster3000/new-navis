# План: калибровка проектного нуля

> **Статус: реализовано.** Кнопка «Калибровка» на вкладке Navis Elevation: выбрать
> точку кликом, ввести её проектную отметку — плагин посчитает сдвиг и применит его ко
> всем отметкам модели. Калибровка хранится отдельно для каждой модели в `offsets.ini`,
> сбрасывается той же кнопкой. Проверено в Navisworks Manage 2021, версия 0.2.0.
>
> План переписан под решение пользователя от 2026-10-20: калибровка по эталону,
> отдельная кнопка на ленте, хранение отдельно для каждой модели. Заменил два
> отложенных плана: `docs/future/project-zero.md` и `docs/future/calibration-button.md`.

## Цель

Дать пользователю указать, где в модели находится проектный ноль, чтобы все отметки
показывались в проектных метрах.

В API Navisworks нет базовой точки проекта, поэтому «правильность» отметки нельзя
проверить заранее — она сверяется вручную с элементом заведомо известной отметки.
На рабочих моделях ноль Navisworks совпал с проектным, но совпадение не гарантировано:
федеративная модель собирается из моделей со своими `Model.Transform`, и общая точка
отсчёта может оказаться где угодно.

## Решения пользователя

| Вопрос | Решение |
|---|---|
| Как выполняется калибровка | **По эталону.** Плагин запоминает отметку выбранного элемента, пользователь вводит известную проектную отметку, плагин сам считает смещение |
| Где хранить | **Отдельно для каждой модели.** У каждого открытого NWF своё смещение, переключение модели переключает калибровку |
| Где интерфейс | **Отдельная кнопка на ленте.** Окно настроек остаётся общей информацией о плагине, калибровка — самостоятельная задача |
| Понятий одно или два | **Одно:** «смещение отметки» в метрах, прибавляемое после перевода в метры. Отдельного понятия «проектный ноль» в коде нет |

## Сценарий пользователя

1. На вкладке **Navis Elevation** нажимается кнопка **«Калибровка»**.
2. Открывается окно «Калибровка отметки»:
   - строка состояния: «Калибровка для этой модели: не задана» либо «задана, смещение
     +0.360 м»;
   - кнопки **«Установить новую калибровку»** и **«Сбросить калибровку»** (вторая гаснет,
     если калибровки нет);
   - кнопка «Закрыть».
3. «Установить новую калибровку» → окно закрывается → включается **режим выбора точки**:
   - в левом верхнем углу вместо обычной подписи: «Выберите точку калибровки», ниже
     «Отметка сейчас: +2.640 м» (значение обновляется при движении мыши), ниже имя
     элемента и «ЛКМ — выбрать точку, Esc — отмена»;
   - элемент под курсором подсвечивается как обычно.
4. **ЛКМ по элементу** → открывается окно «Проектная отметка точки»:
   - «Отметка сейчас: +2.640 м» — то, что плагин показывает сейчас;
   - поле «Проектная отметка, м» с предзаполненным текущим значением;
   - строка «Новое смещение модели: +0.720 м» — пересчитывается на лету;
   - кнопки «ОК» и «Отмена».
5. **ОК** → смещение сохраняется для этой модели, включается режим «Показать отметку»,
   подписи сразу пересчитываются.
6. В обычной подписи, если калибровка есть, добавляются строки **«Отметка откалибрована»**
   и **«Смещение: +0.360 м»** — чтобы было видно, что число уже сдвинуто, и его можно
   было восстановить вручную.
7. **«Сбросить калибровку»** → запись удаляется → отметки снова считаются от нуля
   модели.

## Установленные факты об API

Проверено рефлексией по `Autodesk.Navisworks.Api.dll` из установленного Navisworks 2021.

| Факт | Следствие |
|---|---|
| Диалоговых типов в API нет вообще | Свои окна делаем на WPF, как уже сделано окно настроек |
| У `Plugin` есть только `GetString`, `GetStringSafe`, `TryGetString` | Записать настройки средствами Navisworks нельзя, нужен свой файл |
| У `ModelItem` нет `SetNamedData` / `GetNamedData` | Записать ноль внутрь NWF невозможно, калибровка живёт на стороне пользователя |
| У `Model` есть `Guid` и `SourceGuid` | Ключ, переживающий переименование и перемещение файла |
| У `Document` нет `Guid`, но есть `FileName` и `Title` | Ключ документа — путь к файлу, запасной — Guid модели внутри него |
| `Application.Gui.MainWindow` даёт `IWin32Window` | Своё окно можно сделать модальным, оно встанет поверх Navisworks |
| У `ToolPlugin` есть `MouseDown` и `MouseMove` | Выбор точки кликом реализуем в том же инструменте, что и показ отметки |

## Формула

```
отображаемая отметка = метры(Z) + смещение
```

Смещение всегда в **метрах** и прибавляется **после** перевода: вычитать метры из
футов бессмысленно.

Калибровка по эталону:

```
смещение = проектная отметка (м) − метры(Z_точки)
```

Смещение **заменяет** прежнее, а не прибавляется к нему: если модель уже была
откалибрована и калибруют заново, новое значение считается от сырого `метры(Z)`.
Иначе повторная калибровка накапливала бы ошибку.

## Хранение

Файл `%APPDATA%\NavisElevation\offsets.ini`, одна секция на модель:

    [model]
    Path=C:\models\project.nwf
    Guid=7a3f1c2e-4d5e-4f60-8a71-b2c3d4e5f607
    Offset=0.360

Правила поиска записи для активного документа:

1. по `Guid` любой модели документа — работает, даже если файл переименовали или
   переместили;
2. если не нашлось — по `Path` (путь сравнивается без учёта регистра);
3. если не нашлось — значение по умолчанию из `%APPDATA%\NavisElevation\settings.txt`
   (ключ `ProjectOffset`, для совместимости со старыми версиями).

Запись файла атомарная: сначала во временный файл, потом замена. Файл небольшой,
парсится вручную, без библиотек.

**Чего хранилище не делает:** калибровка не попадает внутрь NWF и не передаётся коллеге.
Тот, кто откроет файл у себя, откалибрует один раз сам.

## Что нашли на первом прогоне

Первый запуск в Navisworks показал три вещи, которых не видно из кода.

### Нумерация кнопок мыши в `ToolPlugin` не документирована

Клик по элементу в режиме выбора точки **не доходил** до обработчика: в логе не было ни
«точка выбрана», ни «клик не попал в элемент», а это единственные ветки, куда попадает
клик. Единственный «тихий» выход из обработчика — проверка `button != 0`.

Вывод: Navisworks передаёт для **левой** кнопки не 0. В API нет ни перечисления кнопок,
ни их значений: перебором по сборке `Autodesk.Navisworks.Api.dll` типа с именами
Left/Middle/Right не нашлось, официальный XML-документ на `ToolPlugin.MouseDown` молчит.

**Уточнено по логу: левая кнопка — 1, правая — 2.**

Что сделано: клик принимается **любой** кнопкой, кроме правой, а фактическое значение
кнопки пишется в лог.

### Очередь сообщений вне модальных окон Navisworks не качается

Окно ввода отметки открывалось отложенно, через `Dispatcher.BeginInvoke`, — из
обработчика мыши. Отложенный вызов ждал очереди сообщений потока, а Navisworks вне
модальных окон её не качает: окно просто не появлялось.

Что сделано: окно открывается **напрямую** из обработчика мыши. Цена решения — вложенный
цикл сообщений внутри события Navisworks; если программа на этом подвиснет, порядок
шагов придётся поменять (сначала ввод отметки из окна на ленте, потом клик по точке).

### Клавиатурный фокус после закрытия окна уходил на ленту

После закрытия окна ввода отметки Esc переставал доходить до плагина: фокус оставался
на ленте, и режим отметки можно было выключить только мышью по кнопке.

Причина была и в нашем коде: `SetFocus` из потока плагина в окно 3D-вида (поток
Navisworks) **молча ничего не делает**, но возвращает ненулевое значение — и мы писали
в лог «Фокус передан в 3D-вид», хотя фокус не переходил. Подробности — в разделе
«Фокус после закрытия окна переносится не туда».

### Enter до плагина не доходит

`Enter` не работает как подтверждение выбора точки: Navisworks перехватывает его сам
(`Esc` при этом доходит). Из подсказки Enter убран, подтверждение — только ЛКМ.

### Калибровка «в ноль» засоряла подпись

Можно было ввести изначальную отметку точки и получить калибровку с нулевым смещением:
отметка не менялась, а плагин писал «Отметка откалибрована». И наоборот — ввести
значение уже сделанной калибровки было нельзя, потому что проверка сравнивала ввод с
**показанной** отметкой.

Что сделано: проверяется **смещение**, а не введённое значение. Смещение обязано быть
ненулевым, иначе «ОК» заблокирована и подсказка говорит «Введите значение, при котором
отметка сдвинется». Так можно и подтвердить уже сделанную калибровку (её значение даёт
ненулевое смещение), и нельзя создать пустую калибровку. Поле ввода открывается пустым:
плагин не подставляет проектную отметку за пользователя.

Запись со смещением ноль калибровкой не считается: в подписи не будет «Отметка
откалибрована», а кнопка «Сбросить калибровку» позволит такую запись удалить.

### Кнопка не умела показывать нажатое состояние

Плагин возвращал `IsChecked` верно — в логе было «отметка=True» при включённом режиме и
«отметка=False» после Esc, — но лента ничего не подсвечивала. Причина в разметке: у
`NWRibbonButton` есть свойство `IsCheckable`, и без него кнопка в принципе не может
быть нажатой. Так сделано у встроенных переключаемых кнопок Navisworks — см.
`RenderTab.xaml` в папке установки.

Побочный эффект был тот же, что у «неработающего Esc»: **Esc до плагина доходит**
(в логе есть «Режим отметки выключен: Esc»), но кнопка оставалась подсвеченной, и
выглядело это как «Esc не отключает режим».

### Состояние выбора точки залипало

`CalibrationSession.IsPicking` не сбрасывалось при выключении режима отметки. Если
выключить режим кнопкой, не выходя из выбора точки, состояние «идёт калибровка»
оставалось навсегда — и кнопка «Показать отметку» переставала подсвечиваться даже при
включённом режиме.

Что сделано: выбор точки отменяется при выключении режима — и по Esc, и кнопкой на
ленте.

### Фокус после закрытия окна переносится не туда

`SetFocus` из потока плагина в окно 3D-вида (поток Navisworks) не даёт эффекта: фокус
остаётся на ленте, и Esc до плагина не доходит — приходится кликать в вид.

Собственная диагностика переноса молчала: она падала вместе с остальным кодом, а
`catch` был безмолвным. Из-за этого в логе не было ни одной строки о переносе — и
казалось, что перенос не вызывается вовсе.

**Причина нашлась, когда `catch` стал писать исключение:**

```
EntryPointNotFoundException: Не удается найти точку входа "GetCurrentThreadId" в DLL "user32.dll".
```

`GetCurrentThreadId` живёт в **kernel32.dll**, а не в user32.dll. Перенос фокуса падал на
первой же строке. Проверено перебором экспортов обеих DLL: `GetCurrentThreadId` есть
только в kernel32, `GetWindowThreadProcessId`, `AttachThreadInput`, `SetFocus`,
`GetFocus`, `SetForegroundWindow` — только в user32.

Что сделано:
- импорт исправлен на `kernel32.dll`;
- **каждый шаг переноса пишется в лог до того, как выполнен**, а `catch` пишет
  исключение со стеком — без этого ошибка выглядела как «перенос не вызывается»;
- `GetWindowThreadProcessId` объявлена правильно: функция возвращает `DWORD`, а не
  указатель, и при объявлении как `IntPtr` на 64-битной системе в значение попадал
  мусор — сравнение потоков давало неправильный ответ;
- фокус переносится из обработчика закрытия окна (`Closed`): он выполняется в потоке
  самого окна, и если это тот же поток, что у окна 3D-вида, `SetFocus` работает
  напрямую;
- в лог пишутся id потоков — поток плагина, поток окна 3D-вида, поток главного окна;
- сообщение в логе больше не врёт: «Фокус возвращён в 3D-вид» означает именно перенос
  фокуса, а не успешное перевключение инструмента.

### Строка «Модель» убрана из подписи

Имя файла модели-источника проектировщику ничего не говорит, а место в подписи
занимает. Убрана и из подписи, и из окна ввода отметки.

### Три команды делили одно поле состояния

Кнопок на ленте стало три, а поле `_lastState` было одно: команды затирали друг друга,
условие «состояние изменилось» срабатывало каждый раз, и лог за минуту набирал
тысячи одинаковых строк. Теперь сравнивается снимок состояния всех кнопок сразу.

### Модель-владелец элемента не находился

В логе при выборе точки было «модель неизвестна». Причина: `FindOwningModel` сравнивал
`model.RootItem` с родителем элемента через `ReferenceEquals`, а обёртка `ModelItem`
каждый раз новая — сравнение всегда ложно.

Из-за этого в подписи не было строки «Модель: …», а калибровка сохранялась без Guid и
держалась только на пути к файлу: переименуешь файл — потеряешь калибровку.

Что сделано: элементы сравниваются по `ModelItem.InstanceGuid` — это устойчивый
идентификатор элемента, в отличие от ссылки на обёртку.

### Нажатой выглядела не та кнопка

Режим показа отметки и режим выбора точки живут в одном инструменте, поэтому обе кнопки
считали себя включёнными. Теперь во время калибровки нажатой показывается
**«Калибровка»**, а «Показать отметку» — не нажатой. После калибровки строка
«Отметка откалибрована» стоит в подписи **первой** и рисуется **красным**.

## Риски

| Риск | Признак | Что делать |
|---|---|---|
| Модальное окно из обработчика мыши вешает Navisworks | Окно не появляется или программа встаёт | Окно ввода открывается напрямую, без отложенного вызова. Если Navisworks на этом зависнет — порядок шагов меняется на «сначала ввод отметки, потом клик»: правка в одном месте плюс тексты |
| Клик не доходит до инструмента | В логе нет «точка выбрана» при явном клике | Клик принимается любой кнопкой, кроме правой, значение пишется в лог. Запасной способ — клавиша `Enter` |
| Клик попал в пустоту | Окно ввода не открылось | Пишем в лог и остаёмся в режиме выбора точки: пользователь кликнет ещё раз |
| Точка выбрана на поверхности, а отметка элемента известна по верху | Отметка «поехала» на толщину элемента | В подсказке прямо сказано: выбирайте точку с известной проектной отметкой, например верх перекрытия |
| Смещение считается не в метрах | Отметка уехала на километры | Смещение всегда в метрах, прибавляется после перевода; в окне это написано |
| Файл модели не сохранён | Калибровка не сохранится | Окно предупреждает: сохраните файл, иначе калибровка останется только в этой сессии |
| Переименование файла модели | Калибровка потерялась | Поиск идёт сначала по `Guid` модели, путь — запасной |
| Сломанная разметка ленты | Пропала вся вкладка | После сборки проверяем атрибуты рефлексией по собранной DLL; вкладка и её кнопки описаны в одном файле |
| Новая панель ленты ломает порядок элементов | Кнопки не в том порядке | Порядок панелей задаётся порядком элементов в разметке: Настройки → Отметка → Калибровка |
